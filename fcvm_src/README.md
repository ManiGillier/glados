# VM Architecture 

## Overview

The **fcvm** (Fran C Virtual Machine) is designed to execute bytecode generated by the Fran C compiler.\
This document describes its architecture, design decisions, and implementation details.

## Design Objectives

The architecture was driven by four core principles:

- **Simplicity**: Minimize architectural complexity to facilitate maintenance and evolution
- **Modularity**: Enable independent development and testing of VM components
- **Performance**: Optimize execution speed for common operations
- **Debuggability**: Provide clear execution traces and error reporting

## Inspirations

Based on these objectives, we adopted a **[stack-based architecture](https://en.wikipedia.org/wiki/Stack-oriented_programming)**,\
drawing inspiration from the **[Java Virtual Machine (JVM)](https://en.wikipedia.org/wiki/Java_virtual_machine)**.

### Stack-Based vs Register-Based


| Aspect              | Stack-Based (fcvm)           | Register-Based (e.g., Lua VM) |
|---------------------|------------------------------|-------------------------------|
| **Storage**         | Operand stack (LIFO)         | Virtual registers             |
| **Instructions**    | Compact, implicit operands   | Explicit operand addressing   |
| **Complexity**      | Simple to implement          | More complex logic            |
| **Bytecode Size**   | Smaller (fewer bytes/instr)  | Larger (operand encoding)     |

We chose a stack-based approach for the following reasons:

1. **Simpler bytecode generation**: The compiler doesn't need to perform register allocation
2. **Easier evolution and extensibility**: The stack-based architecture provides natural extension points for future enhancements:

## Stack

The stack is implemented as a contiguous array of bytes with the following characteristics:

- **Data type**: Array of unsigned bytes (`uint8_t[]`)
- **Element size**: 8 bytes per element (64-bit integers)
- **Alignment**: All operations push/pop exactly 8 bytes
- **Stack size**: Always a multiple of 8 bytes

#### Stack Management

To optimize performance, the VM maintains two pointers:

- **Stack Pointer (SP)**: Points to the current top of the stack (modified with function call and return)
- **Stack Counter**: Tracks the number of elements, avoiding recalculation after each operation

```
Stack Memory Layout:
┌─────────────┬─────────────┬─────────────┬─────────────┐
│  Element 0  │  Element 1  │  Element 2  │     ...     │
│  (8 bytes)  │  (8 bytes)  │  (8 bytes)  │             │
└─────────────┴─────────────┴─────────────┴─────────────┘
      ↑
      SP (Stack Pointer)
```

### Initialization

By default, the stack is initialized with **8 zero bytes** (one 64-bit zero value), \
representing the default return value of the program:

```
Initial State:
┌─────────────┐
│ 0x00000000  │  ← Default return value (64-bit zero)
│ 00000000    │
└─────────────┘
      ↑
      SP
```

### Basic Operations

| Operation | Description | Stack Effect |
|-----------|-------------|--------------|
| **PUSH**  | Push 8 bytes onto the stack | SP unchanged, Counter += 1 |
| **POP**   | Remove 8 bytes from the stack | SP unchanged, Counter -= 1 |

### Example Execution

```
Operation: PUSH 42

Before:                    After:
┌─────────────┐           ┌─────────────┐
│      0      │           │     42      │  
└─────────────┘           ├─────────────┤
      ↑                   │      0      │  ← SP
      SP                  └─────────────┘
Counter: 1                Counter: 2
```

## CallStack 

The **call stack** manages function calls and returns, enabling the VM to:
- Navigate between functions
- Restore execution context after function returns
- Maintain function-local state
- Detect program termination

### Memory Layout

The call stack is implemented as a contiguous array of frame records:\
By default, the call stack is initialized as an **empty array**.

- **Data type**: Array of tuples `[(PC, SP)]`
  - **PC** (Program Counter): Return address (next instruction after CALL)
  - **SP** (Stack Pointer): Stack state at call time

```
Call Stack Structure:
┌─────────────────────────────────┐
│  Frame 0: (PC: 0, SP: 0)        │  ← Program entry point
├─────────────────────────────────┤
│  Frame 1: (PC: 12, SP: 16)      │  ← First function call
├─────────────────────────────────┤
│  Frame 2: (PC: 57, SP: 24)      │  ← Current function
└─────────────────────────────────┘
                ↑
        Call Stack Counter
```

### Function call mechanism

When executing `CALL <address>`:

1. **Save current context**: Push `(PC + 1, SP)` onto the call stack
   - `PC + 1`: Address of the instruction following CALL
   - `SP`: Current stack pointer (preserves caller's stack)
2. **Jump to function**: Set `PC = <address>`

When executing `Ret`:

1. **Pop frame**: Retrieve `(saved_PC, saved_SP)` from call stack
2. **Restore context**: 
   - Set `PC = saved_PC` (return to caller)
   - Set `SP = saved_SP` (restore stack state)
3. **Check termination**: If call stack is empty after pop, **terminate program**

## Zero flag

The **Zero Flag** is a single-bit register used for conditional branching and control flow decisions.\
It stores the result of comparison and test operations, \
enabling the implementation of `if`, `while`, and other conditional constructs.

- **Data type**: `unsigned char`
- **Default value**: `1` 

### Flag Semantics

The Zero Flag follows this logic:

| Condition | Zero Flag Value |
|-----------|-----------------|
| Top stack element **!= 0** | `1` (true) |
| Top stack element **== 0** | `0` (false) |

## End cases

The VM can terminate execution in two ways:
1. **Normal termination**: Program completes successfully
2. **Error termination**: An error condition is encountered

### Successful Execution

The program terminates normally when:
- A `Ret` instruction is executed from the main function
- The call stack becomes empty after the return

**Exit behavior**:
- **Exit code**: `0` (or user-defined return value)
- **Return value**: Top element of the operand stack at termination

### Error Termination

When an error occurs, the VM immediately halts execution and returns **exit code 84**.

#### 1. File Format Errors

| Error | Condition | When Detected |
|-------|-----------|---------------|
| **Invalid Magic Number** | Bytecode header doesn't match expected value | VM initialization |
| **Invalid Entry Point** | Entry address out of bounds | Loading phase |

##### 2. Arithmetic Errors

| Error | Condition | Example |
|-------|-----------|---------|
| **Division by Zero** | `Div` with divisor = 0 | `10 / 0` |
| **Modulo by Zero** | `Mod` with divisor = 0 | `10 % 0` |

##### 3. Stack Errors

| Error | Condition | Cause |
|-------|-----------|-------|
| **Stack Overflow** | Operand stack exceeds maximum capacity | Too many PUSH operations without POP |
| **Stack Underflow** | Attempt to POP from empty operand stack | More POP than PUSH operations |

##### 4. Call Stack Errors

| Error | Condition | Cause |
|-------|-----------|-------|
| **Call Stack Overflow** | Call stack exceeds maximum depth | Too many nested function calls (e.g., infinite recursion) |
